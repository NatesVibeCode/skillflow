# Find existing code that fits the requested work

Use this guide when locating implementations or deciding what to reuse. Discovery
is an optional aid to the operator's selected task. It does not gate development,
composition, printing, execution or delivery.

Start with the requested behavior and selected checkout. Use `rg` and current
source directly when sufficient. For cross-repository relationships, use the
existing discovery CLI and dictionary queries in [the method](references/method.md).
Search only the selected repositories and relevant terms. Configuration paths and
catalog entries do not select a different product or authorize unrelated changes.

Read promising implementations and their actual callers. Check the typed inputs,
outputs, effects and behavior that matter to the receiving consumer. Reuse what
fits, extend its existing boundary where useful, and build only missing behavior.
A matching name, identical bytes or a successful command does not establish fit.
A stale index is a navigation limitation: follow current source and continue the
product work. Refresh an index only when needed for the selected outcome.

Give a concise answer with useful source links and material gaps. No discovery
session, decision.json, final.md, freshness approval, projection refresh or sealed
discovery receipt is required. Do not rebuild working capabilities to repair a
navigation record. Product types, wiring, effect authority, execution identities
and actual consumer checks remain the responsibility of their existing owners.
